# 📊 Dashboard Project

Аналитический дашборд для мониторинга складских операций и работы сотрудников.

Проект разработан на Python + Streamlit и предназначен для получения данных из PostgreSQL, отображения аналитических отчетов, поиска по результатам, выгрузки данных в Excel, мониторинга текущих складских процессов и сбора предложений по развитию дашборда.

---

## 🚀 Возможности

### 📊 Аналитические отчеты

Дашборд позволяет выбирать и одновременно отображать несколько аналитических отчетов.

В проекте доступны отчеты:

* Не выданные заявки
* Неотобранные артикулы с разбивкой на подтипы
* Статистика по отобранным и неотобранным артикулам
* Статусы заявок отгрузки
* Количество отборов сотрудников по волнам
* Отборы сотрудников по волнам
* Средняя скорость отбора в час
* Выданные клиентам заказы
* Операции по ресурсам

Список отчетов хранится централизованно в файле `queries.py`.

---

## 🔎 Поиск по таблицам

Для отчетов с большим количеством данных предусмотрен встроенный поиск.

Поиск выполняется сразу по всем столбцам таблицы.

Доступны следующие функции:

* 🔎 поиск по таблице;
* ⌨️ запуск поиска клавишей `Enter`;
* 🔎 запуск поиска кнопкой «Найти»;
* ✖️ очистка поискового запроса;
* отображение только найденных строк;
* поиск без изменения исходных данных отчета.

Поиск выполняется по текстовому представлению значений всех столбцов, поэтому можно искать как по текстовым полям, так и по числовым значениям, датам и другим данным.

## 📥 Выгрузка в Excel

Результаты отчетов можно скачать непосредственно из интерфейса дашборда.

Для каждого отчета доступна кнопка:

**⇩ Скачать**

Данные выгружаются в формате:

`.xlsx`

Для создания Excel-файла используется библиотека OpenPyXL.

### Экспорт учитывает поиск

Если перед скачиванием был выполнен поиск, в Excel попадут только найденные строки.

Например:

1. открыть отчет;
2. ввести значение в поле поиска;
3. нажать «Найти»;
4. проверить найденные строки;
5. нажать «⇩ Скачать».

В результате будет сформирован Excel-файл только с отфильтрованными данными.

Если поиск не выполнялся, в Excel выгружается полный результат отчета.

## 🛠️ Разработка и предложения

В проекте предусмотрена отдельная страница «Разработка» для сбора предложений пользователей по развитию аналитического дашборда.

Пользователь может предложить:

* новый отчет;
* изменение существующего отчета;
* улучшение интерфейса;
* исправление найденной проблемы;
* новую функциональность;
* другое изменение, связанное с развитием проекта.

### 💡 Добавление предложения

Для добавления предложения используется кнопка:

**➕ Предложить изменение**

Открывается всплывающее окно, в котором необходимо указать:

* тему или краткое описание;
* имя автора;
* текст предложения.

Также к предложению можно прикрепить файлы.

### 📎 Вложения

Поддерживается прикрепление нескольких файлов к одному предложению.

Можно добавлять, например:

* скриншоты `PNG`, `JPG`, `JPEG`, `WEBP`, `GIF`;
* PDF-файлы;
* Excel-файлы;
* Word-документы;
* текстовые файлы;
* CSV-файлы.

Изображения отображаются непосредственно в предложении, остальные файлы доступны для скачивания.

Вложения сохраняются локально в каталоге:

`logs/suggestions/`

### 📋 Статусы предложений

Каждое предложение имеет один из двух статусов:

* 🟡 В работе
* 🟢 Выполнено

На странице «Разработка» отображается статистика:

* 💡 Всего предложений;
* 🟡 В работе;
* 🟢 Выполнено.

Также доступна фильтрация предложений по статусу.

### 📖 Просмотр предложений

Предложения отображаются в свернутом виде.

В списке видны:

* тема предложения;
* автор;
* текущий статус.

При нажатии на предложение оно раскрывается и показывает:

* дату создания;
* подробное описание;
* вложения;
* информацию о выполнении.

Это позволяет сохранять страницу компактной даже при большом количестве предложений.

## 🔐 Административная панель

В проекте предусмотрена отдельная административная страница.

Доступ к странице защищен паролем.

Пароль администратора **не хранится в исходном коде**. Он задается через переменную окружения:

```env
ADMIN_PASSWORD=your_admin_password
```

Административная панель позволяет просматривать статистику использования дашборда, пользователей онлайн и управлять предложениями пользователей.

### 📈 Статистика использования

В административной панели отображаются:

* количество уникальных посетителей;
* общее количество действий;
* количество сессий;
* количество действий за текущий день;
* популярные отчеты;
* ежедневная активность;
* последние действия пользователей;
* IP-адреса пользователей.

### 🌐 Пользователи онлайн

В отдельной вкладке отображаются пользователи, которые были активны в течение последних 5 минут.

Для пользователя отображается:

* 🟢 статус;
* IP-адрес;
* время последней активности.

Статус «онлайн» определяется по последней зафиксированной активности пользователя.

Это не постоянное сетевое подключение, а определение активности по событиям, которые приложение записывает в журнал.

### 💡 Управление предложениями

В административной панели отображаются все предложения пользователей.

Администратор может:

* просматривать тему предложения;
* видеть автора;
* просматривать подробное описание;
* открывать вложения;
* скачивать прикрепленные файлы;
* устанавливать статус «Выполнено»;
* возвращать предложение в статус «В работе»;
* удалять предложения.

При установке статуса «Выполнено» сохраняются:

* дата выполнения;
* пользователь, выполнивший изменение статуса.

## 📝 Логирование

В проекте реализовано централизованное логирование действий пользователей.

Для хранения логов используется SQLite.

Файл базы логов:

```text
logs/dashboard_logs.db
```

### Что логируется

В журнал записываются:

* посещения страниц;
* запуск отчетов;
* параметры запросов;
* время действия;
* User-Agent браузера;
* `session_id`;
* IP-адрес пользователя, если он доступен приложению.

### 🌐 Логирование посещений страниц

Логирование посещений страниц выполняется централизованно в `app.py`.

При переходе пользователя между страницами фиксируется действие:

```text
page_visit
```

В качестве названия страницы используется название текущей страницы навигации.

Например:

```text
Посещение страницы → 🏠 Главная страница
Посещение страницы → 📊 Дашборд отгрузки
Посещение страницы → 📦 Выдача клиенту
Посещение страницы → 🛠️ Разработка
Посещение страницы → 🔐 Администрирование
```

Повторные `rerun` одной и той же страницы не создают новое событие посещения, пока пользователь не перейдет на другую страницу.

### 📊 Логирование запуска отчетов

Запуск отчета записывается как действие:

```text
view_report
```

При наличии параметров отчета они сохраняются в поле `params`.

Например, для параметризованного отчета могут сохраняться:

* номер заявки;
* выбранный диапазон дат;
* другие параметры запроса.

Для часто используемых отчетов статистика строится на основе записей `view_report`.

### 🌐 Определение IP

IP-адрес пользователя определяется непосредственно из WebSocket-соединения Streamlit.

Приложение получает адрес клиента из текущей Streamlit-сессии.

Если определить IP невозможно, записывается:

```text
unknown
```

### 👤 Сессии

Для каждой Streamlit-сессии создается уникальный `session_id`.

Он используется для связи действий одного сеанса работы пользователя.

Информация о сессиях хранится в таблице:

```text
user_sessions
```

В ней сохраняются:

* `session_id`;
* IP-адрес;
* время первого посещения;
* время последней активности;
* количество посещений.

### 👥 Уникальные посетители

Количество уникальных посетителей в административной статистике рассчитывается по уникальным IP-адресам.

Это означает, что два пользователя, работающие с одного IP-адреса, будут учитываться как один уникальный сетевой посетитель.

Отдельно считается количество уникальных `session_id`.

Таким образом:

* **Уникальные посетители** → уникальные IP;
* **Сессии** → уникальные `session_id`.

### 🟢 Пользователи онлайн

Пользователь считается активным, если в `user_sessions` зафиксирована активность в течение последних 5 минут.

При расчете используется:

```text
last_visit
```

Список пользователей группируется по IP-адресу.

### 🗄️ Структура логов

Основные таблицы SQLite:

```text
user_actions
user_sessions
```

`user_actions` содержит отдельные действия пользователей.

`user_sessions` содержит информацию о пользовательских сессиях и их последней активности.

### Навигация

Для навигации используется `st.navigation()`.

`app.py` является точкой входа и роутером приложения. Он регистрирует страницы через `st.Page()` и запускает выбранную страницу.

В боковом меню доступны:

* 🏠 Главная страница
* 📊 Дашборд отгрузки
* 📦 Выдача клиенту
* 🛠️ Разработка
* 🔐 Администрирование

`app.py` также отвечает за:

* создание `session_id`;
* централизованное логирование посещений страниц;
* запуск выбранной страницы.

Основная логика главной страницы находится в:

```text
pages/Главная страница.py
```

#### `app.py`

Главный файл приложения и роутер навигации.

Отвечает за:

* настройку приложения;
* настройку ширины страницы;
* формирование навигации;

* создание пользовательской сессии;

#### `pages/Главная страница.py`

Главная страница аналитического дашборда.

# 🔐 Настройка подключения к PostgreSQL

Параметры подключения рекомендуется хранить в `.env`.

Пример:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=your_password
```

> Файл `.env` не должен публиковаться в GitHub.

Добавьте его в `.gitignore`:

```text
.env
```

---

# 🔑 Настройка пароля администратора

Пароль административной панели хранится в `.env`.

Добавьте:

```env
ADMIN_PASSWORD=your_admin_password
```

Например:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=your_database_password

ADMIN_PASSWORD=your_admin_password
```

Пароль администратора не должен находиться непосредственно в `admin.py` или другом исходном коде.

В коде пароль загружается через:

```python
Config.ADMIN_PASSWORD
```

`.env` добавлен в `.gitignore` и не должен отправляться в GitHub.

# 🗄 Настройка базы данных

Проект использует PostgreSQL в качестве основной базы данных.

Для ускорения работы используется механизм кеширования Streamlit:

```python
@st.cache_data
```

Подключение к PostgreSQL кешируется отдельно:

```python
@st.cache_resource
```

* Логирование вынесено в отдельный модуль.
* Используется SQLite для хранения статистики использования и предложений.
* Реализовано централизованное логирование посещений страниц.

* Реализован просмотр последних действий пользователей.
* Реализован поиск по всем столбцам таблицы.

* Реализована кнопка очистки поиска.
* Реализована фильтрация результатов.

* Изображения отображаются непосредственно в предложениях.

# 🔒 Безопасность

Не рекомендуется хранить в репозитории:

* пароли от PostgreSQL;
* пароль администратора;
* `.env`;
* персональные данные пользователей;
* production-базы данных;
* реальные логи пользователей;
* загруженные пользователями файлы.

Перед публикацией проекта убедитесь, что `.gitignore` содержит:

```text
.env
.venv/
__pycache__/
*.pyc
logs/
*.db
*.sqlite3
```

Файл `.env` должен находиться только на компьютере, где запускается приложение.
